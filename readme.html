Maven

eclipse-java-maven-template

A Java + Maven course-project template: JUnit 5 tests, JaCoCo + ReportGenerator coverage, Doxygen + Javadoc API docs, a full mvn site, and numbered .bat/.sh scripts that take you from a fresh clone to a built, tested, documented, releasable project. Use it as the starting point for a CEN207/CEN206/CEN429-style term project (see from-topic-en.md / from-topic-tr.md).

Quick start

Prerequisites (JDK 17+, Maven, Doxygen, lcov, ReportGenerator, coverxygen, gh): see install-en.md / install-tr.md. Once installed:

Windows (cmd/PowerShell):

git clone https://github.com/<your-account>/<your-repo>.git
cd <your-repo>
1-configure-git-hooks.bat
7-build-app.bat
8-run-app.bat 6 "*" 7

Linux / WSL (bash):

git clone https://github.com/<your-account>/<your-repo>.git
cd <your-repo>
./1-configure-git-hooks.sh
./7-build-app.sh
./8-run-app.sh 6 '*' 7

7-build-app is the one script that does everything (build, test, both coverage-report families, both documentation-coverage families, API docs, the full site) - see use-template-en.md / use-template-tr.md for the full walkthrough.

The numbered scripts

Each has a Windows .bat and a Linux/WSL .sh with the same behavior. Run them in this order; 1-5 are one-time setup, 7-10 are the ones you use every day.

# Script What it does
1 1-configure-git-hooks Installs pre-commit (Astyle formatting + sanity checks) and pre-push into .git/hooks/.
2 2-create-git-ignore One-time bootstrap: regenerates .gitignore from the toptal.com API. Not for routine use - see the warning in the script.
3 3-install-package-manager Installs/verifies Chocolatey+Scoop (Windows) or checks apt/installs a per-user JDK 17, Maven 3.9.9 and .NET SDK 8+ if what is already on the machine is too old (Linux/WSL).
4 4-install-required-apps Installs everything else this repo's scripts use: Astyle, Doxygen, Graphviz, lcov, the ReportGenerator global tool, coverxygen, gh. Safe to re-run.
5 5-format-code Formats every .java file with Astyle (astyle-options.txt, --mode=java).
7 7-build-app The main script. mvn clean test package, JaCoCo, Doxygen, ReportGenerator (coverage + doc-coverage), coverxygen + genhtml, mvn site, and packages everything into release/.
8 8-run-app Runs the built jar: 8-run-app <number> <+\|-\|*\|/> <number> (a demo 6 * 7 if you pass no arguments).
9 9-run-webpage Serves the already-built static site (with every report) over a local HTTP server at http://localhost:8000/ - required for the report pages' <iframe>s, which most browsers block under file://. Pass --serve for a live mvn site:run dev server instead.
10 10-release Builds everything, zips the site, and publishes a GitHub Release with the GitHub CLI. --dry-run to preview without publishing. See releases-en.md.

Utilities: delete_desktop_ini (removes Google Drive's desktop.ini litter), init-submodules / update-submodules (no-ops today - this template has no submodules, kept for parity with the C/C++ template).

Live site

https://ucoruh.github.io/eclipse-java-maven-template/ - the landing page above, the full menu, and every report below, each in its own framed page. Rebuilt and redeployed on every push to main by .github/workflows/pages.yml.

Reports and where they land

Everything below is produced by 7-build-app into calculator-app/target/site/ (gitignored, not committed) and explained in full, with what each one shows and why there are two families, on the site's own “Which report is which?” page (calculator-app/src/site/markdown/tool-catalog.md, bilingual EN+TR). Open the site with 9-run-webpage (serves it over a local HTTP server, required for the report pages' <iframe>s) and use the Reports menu - each entry there is that report shown inline, with “Open in a new tab” and “Download (zip)” buttons.

Private repositories: releases and the site, in short

This template repository is public, so its own site above deploys automatically. Your clone/fork for a course project is most likely private, and GitHub Free does not run Pages on a private repo - but Releases do, so 10-release (or a pushed vX.Y.Z tag, via release.yml) publishes every report plus site.zip (unzip -> open index.html) as a GitHub Release instead; pages.yml detects the private repo and skips its deploy with an explanation, unless you set the PAGES_ON_PRIVATE repository variable after getting GitHub Pro (e.g. via the free GitHub Student Developer Pack). Add your instructor as a collaborator so they can see your private releases. Full walkthrough: releases-en.md / releases-tr.md.
